# Mementorize — Web (Next.js)

Interface de Mementorize : connexion / inscription (phase 3), liste et ajout de ses fiches (citations et vocabulaire anglais), écran de révision (phases 4 et 5), et éditeur de cartes mentales (phase 6).

## Prérequis

`apps/api` doit tourner (voir [../api/README.md](../api/README.md)) : cette interface ne fait qu'appeler son API en HTTP, elle n'a pas sa propre base de données.

## Démarrage

```bash
cp .env.example .env.local   # API_URL, par défaut http://localhost:3000
pnpm --filter web dev        # http://localhost:3001 (le 3000 est déjà pris par l'API)
```

## Organisation

- `proxy.ts` — s'exécute avant chaque requête : sans cookie de session, redirige vers `/login` (vérification « optimiste », la vraie vérification du token est faite par l'API).
- `app/(auth)/` — groupe de routes (les parenthèses n'apparaissent pas dans l'URL) : `/login`, `/register`, les Server Actions d'authentification et `/session-expired` (Route Handler qui efface un cookie périmé).
- `app/anglais/` — l'espace Anglais en trois onglets (v0.4, MEM-24) : `layout.tsx` affiche l'en-tête et un h1 masqué (MEM-28), les onglets sont dans le second bandeau de l'en-tête (`sub-nav.tsx`, MEM-29) ; `page.tsx` = Apprendre · Réviser (`/anglais` ; sans rien à apprendre mais avec des éléments « En attente », un lien vers la Liste filtrée, `/anglais/liste?etat=Waiting`, MEM-61), `liste/` = le tableau (`/anglais/liste`), `ajouter/` = la saisie (`/anglais/ajouter`, `add-vocabulary-form.tsx`, en deux blocs Anglais / Français partagés avec la modification depuis la liste, `vocabulary-fields.tsx`, MEM-43, puis la thématique du couple, et la case « Ajouter à la file d'apprentissage » (MEM-62, cochée à l'ouverture de l'onglet, conservée d'un ajout à l'autre ; décochée, l'élément est « En attente »), avec les thématiques déjà utilisées en suggestions (`<datalist>`) et conservée d'un ajout à l'autre, MEM-51 ; en face de chaque champ, un lien « Traduire » vers DeepL ou Google Traduction selon les Réglages, `lib/translate-url.ts`, MEM-44, hors de l'ordre de tabulation pour garder la saisie au clavier rapide ; MEM-27 : curseur dans le premier champ, confirmation qui rappelle l'élément, formulaire vidé pour enchaîner, erreurs affichées sous leur champ). `import-export/` = l'onglet Import / export (`/anglais/import-export`, MEM-52) : l'export CSV est un simple lien vers `import-export/export/route.ts`, qui relaie le fichier de l'API avec le jeton de la session ; le séparateur choisi dans les Réglages y est rappelé. L'import (`import-section.tsx`, MEM-53) : un fichier choisi ou glissé est décodé par une Server Action (première ligne d'en-têtes toujours ignorée, UTF-8 avec ou sans BOM, 1 Mo au plus, `serverActions.bodySizeLimit` à 2 Mo dans `next.config.ts`), analysé par l'API, puis affiché en grille avec le statut de chaque ligne (à importer, doublon, erreur), un résumé et un filtre ; si le fichier semble utiliser l'autre séparateur, un bouton change le réglage et relit le fichier. Sous la grille, « Importer N éléments » (MEM-54 ; éléments « En attente », MEM-62) demande une confirmation, puis renvoie le fichier pour l'intégration ; un message donne le résultat, avec des liens vers la Liste et Apprendre · Réviser. Sur téléphone, les onglets défilent et l'onglet actif est ramené à l'écran (`sub-nav.tsx`). Citations et Cartes mentales gardent `spaces/space-page.tsx`.
- `app/anglais/vocabulary-table.tsx` — le vocabulaire en tableau (MEM-16 à MEM-18) : tri par colonne (thématique comprise, MEM-51) et filtres (recherche, état, thématique — MEM-56 : toutes, chacune de celles utilisées, ou sans thématique), logique dans `lib/vocabulary-table.ts` ; pagination dans le navigateur (`pagination.tsx`, MEM-58 : 20, 50 ou 100 éléments par page, préférence du compte ; tous les éléments restent chargés, seules les lignes de la page sont affichées ; une recherche, un filtre, un tri ou un autre nombre par page ramène à la page 1) ; `vocabulary-actions.tsx` : ajouter une ligne « En attente » à la file d'apprentissage ou l'en retirer (MEM-63), la modifier et la supprimer (MEM-19, MEM-20). Suppression en masse (MEM-59) : une case par ligne, celle de l'en-tête pour la page, puis « Sélectionner les N éléments » de la recherche et des filtres (façon Gmail) ; `selection-bar.tsx` affiche la barre d'actions (« Ajouter à la file », « Retirer de la file » dans l'ordre de la liste, MEM-63, et « Supprimer ») et la confirmation, la suppression passe par `POST /vocabulary/delete` en une requête. La sélection est conservée d'une page à l'autre, effacée quand la recherche ou un filtre change.
- `app/citations/`, `app/cartes-mentales/`, `app/anglais/` — les trois espaces par sujet (MEM-2). Chaque route se contente de dire quel espace elle affiche ; la liste des espaces (type de fiche, libellé, adresse, onglets du sous-menu) est dans `lib/spaces.ts`, avec `activeSpace()` qui dit à quel espace appartient une adresse.
- `app/spaces/space-page.tsx` — Server Component commun aux trois espaces : récupère l'utilisateur et les fiches du type de l'espace côté serveur, avec le token de la session. Sous le titre, le nombre de cartes dues pour ce sujet (`GET /reviews/due?type=…`, MEM-3) ; un espace vide affiche un message propre au sujet, défini dans `lib/spaces.ts`.
- `app/icon.svg`, `app/favicon.ico`, `app/apple-icon.png` — la favicône (MEM-13) : un M blanc sur un carré arrondi teal, agrandi de 25 % par MEM-35 (même dessin que le logo). Next.js ajoute lui-même les balises `<link>` ; `proxy.ts` laisse passer ces fichiers sans session, pour la page de connexion. `favicon.ico` (16, 32 et 48 px) sert aux navigateurs qui ne lisent pas le SVG ; `apple-icon.png` (180 px, sans coins arrondis : iOS les ajoute) sert au raccourci d'écran d'accueil.
- `app/page.tsx` — la racine `/` redirige vers l'espace choisi dans les Réglages (`GET /preferences`, MEM-6), Anglais par défaut. La connexion et le lien de l'e-mail de rappel passent par là.
- `app/items/` — formulaire d'ajout, citation ou mot de vocabulaire (client component + Server Action).
- `app/review/` — écran « À réviser » : une carte à la fois, « Afficher la réponse », puis les boutons d'auto-évaluation colorés de `rating-buttons.tsx` (MEM-46) : « À revoir » (rouge), « Difficile » (orange), « Bien » (jaune) et « Appris » (vert). Raccourcis, rappelés dans l'infobulle de chaque bouton : `Espace` pour révéler, `1` à `4` pour répondre. « Appris » n'est pas une note : pour le vocabulaire, il sort l'élément de la révision (MEM-22), et le tableau de l'espace Anglais permet de le remettre en apprentissage ; pour une citation ou une branche de carte mentale, seule cette carte sort de la révision (MEM-48), et la page de l'espace (ou de la carte mentale) propose « Remettre en révision » (`app/items/relearn-card-button.tsx`). Une séance (`review-session.tsx`, MEM-47) porte sur les cartes à réviser à son ouverture, dont la pile est gardée dans le navigateur : une carte notée « À revoir » est enregistrée puis remise en bas de la pile, jusqu'à ce qu'elle reçoive une autre réponse ; les compteurs du menu sont mis à jour à la fin de la séance. Avec `?type=Quote|Vocabulary|MindMap` (bouton « Réviser l'anglais » d'un espace, MEM-4), seules les cartes de ce sujet sont proposées, et la fin de la séance ramène à l'espace. `facesOf()` (dans `page.tsx`) décide du recto et du verso selon le type de carte : auteur + premiers mots pour une citation, mot anglais ou traduction pour le vocabulaire.
- `app/apprendre/` — le processus d'apprentissage du vocabulaire (MEM-21), distinct de la révision : une session de cinq éléments « À apprendre » au plus (`GET /learning/session`), d'abord découverts (anglais, puis traduction et exemple, sans note), puis notés une fois sur la carte français → anglais (`POST /learning/:itemId`), ce qui les fait passer « En cours d'apprentissage ». Mêmes raccourcis qu'en révision ; récapitulatif en fin de session. Les réponses de l'étape 2 restent dans le navigateur et ne sont envoyées qu'à la fin de la session, dans leur ordre : « Arrêter » (ou quitter la page) laisse tous les éléments « À apprendre ». L'action ne rafraîchit pas la page : après la dernière note, elle afficherait « Rien à apprendre » à la place du récapitulatif.
- `app/mind-maps/` — cartes mentales (phase 6), voir ci-dessous.
- `app/reglages/` — choix de la page d'accueil (`home-space-form.tsx`, MEM-6), délai sous les boutons de révision (`review-form.tsx`, MEM-49 : masqué par défaut, il s'applique à la révision et à l'étape 2 de l'apprentissage), service des boutons « Traduire » (`translator-form.tsx`, MEM-44), séparateur des fichiers CSV (`csv-form.tsx`, MEM-55 : point-virgule par défaut, ou virgule ; `lib/csv-separator.ts`) et réglages du rappel par e-mail (phase 11), à l'adresse `/reglages` : activation, heure, et le fuseau horaire du navigateur, envoyé avec ; bouton « e-mail de test ».
- `app/unsubscribe/` — page publique ouverte depuis le lien d'un e-mail de rappel. La désinscription se fait au clic sur le bouton, pas à l'ouverture du lien : certaines messageries ouvrent d'elles-mêmes les liens des e-mails reçus.
- `app/health/route.ts` — `GET /health`, public : `200` si l'API (et donc la base) répond, `503` sinon. C'est ce que surveille Uptime Kuma : toute la chaîne, de Traefik à la base.
- `app/speech/speak-button.tsx`, `lib/speech.ts` — la prononciation de l'anglais (MEM-37, MEM-39). D'abord l'audio généré par Kokoro sur le serveur (MEM-39), servi par `app/prononciation/[id]/route.ts` (qui relaie l'API avec le jeton de session) à une adresse qui porte une empreinte de l'anglais (`lib/pronunciation-url.ts`, pour le cache), et chargé à l'avance ; s'il manque, la voix du navigateur (américaine de préférence). Comportement (MEM-37) : bouton haut-parleur à droite du texte anglais sur les cartes de vocabulaire (révision, apprentissage), raccourci P, masqué sans voix anglaise ; quand l'anglais apparaît comme réponse (français → anglais, étape 2 de l'apprentissage), il est lu automatiquement (MEM-38), depuis le geste qui révèle la réponse. Synthèse vocale du navigateur (`speechSynthesis`), voix en-GB de préférence, repli sur une autre voix anglaise ; tout ce qui en dépend est dans `lib/speech.ts`, seul fichier à changer pour passer à un service dans le cloud.
- `app/logo.tsx` — le logo (MEM-32) : le monogramme de la favicône sert de première lettre, suivi de « ementorize » en Outfit 600 ; le pied du « M » blanc repose sur la ligne de base et son sommet est à la hauteur d'une majuscule (MEM-35, proportions en `em` commentées dans `globals.css`) ; embarquée par `next/font/local` (`app/fonts/`, licence OFL) ; lien vers l'accueil, annoncé « Mementorize », variante `mark` (monogramme seul).
- `app/app-header.tsx` — en-tête commun, placé avant le `<main>` de la page, en deux bandeaux sur toute la largeur (MEM-29) : un bandeau neutre (nom, icônes, menu) et un bandeau teinté pour le sous-menu de l'espace actif (`sub-nav.tsx`), présent même vide pour que la page ne saute pas ; l'entrée active du menu s'y raccorde comme l'onglet d'un classeur. À partir de 920 px, le bandeau 1 tient sur une ligne (logo │ menu … Réglages, avatar, MEM-33) ; en dessous, deux lignes. La colonne fait 960 px ; les pages qui se lisent mieux étroites (révision, apprentissage, réglages, profil, citations, cartes mentales) prennent `page--reading` : contenu limité à 576 px, aligné à gauche de la colonne, sous le logo. Il récupère lui-même les compteurs du menu et le profil (les pages n'ont plus rien à lui passer) : le nom de l'application et deux icônes à droite (`header-actions.tsx`, MEM-9 : l'engrenage, seul accès aux Réglages, et l'avatar du compte, avec les initiales du prénom et du nom (`lib/initials.ts`)), puis le menu. Chaque page a son propre h1 et un titre d'onglet du navigateur (« Liste · Anglais · Mementorize », MEM-28).
- `app/account-menu.tsx` — la popup de l'avatar (MEM-10) : initiales, nom, e-mail, « Profil » et « Déconnexion ». Elle suit le modèle « menu button » du guide WAI-ARIA : flèches pour passer d'une entrée à l'autre, Échap ou un clic à l'extérieur pour fermer, focus rendu à l'avatar.
- `app/profil/` — le profil ouvert depuis la popup (MEM-11) : l'e-mail en lecture seule, le prénom et le nom, facultatifs (`GET/PUT /profile`, 80 caractères au plus chacun, `lib/profile.ts`). `lib/initials.ts` en tire les initiales de l'avatar et le « Prénom Nom » de la popup ; après l'enregistrement, tout le layout est rafraîchi.
- `app/main-nav.tsx` — le menu (MEM-5) : Anglais, Cartes mentales, Citations, Tout réviser. Chaque espace et « Tout réviser » portent leur nombre de cartes dues, ou une coche dans une pastille claire quand il n'y a rien à réviser. Un Client Component, parce que seul le navigateur connaît l'adresse courante (`usePathname`, `useSearchParams`) : la révision d'un seul sujet met ce sujet en évidence, l'éditeur de cartes mentales relève de Cartes mentales. Sur téléphone (< 640 px), le même menu devient une barre fixe en bas de l'écran, avec une icône, un libellé court et le compteur de chaque entrée (MEM-30, tout en CSS) ; le bandeau du sous-menu n'y apparaît que si l'espace en a un. En haut, sur téléphone : logo │ nom de l'espace ou de la page (`header-title.tsx`, MEM-34), qui y tient lieu de h1 (le h1 masqué `.page__sr-title` est alors retiré) ; tronqué si la place manque, monogramme seul sous 360 px.
- `lib/session.ts` — le cookie de session (httpOnly) qui contient le JWT renvoyé par l'API.
- `lib/api.ts` — client HTTP vers l'API, **côté serveur uniquement** (`import 'server-only'`).
- `lib/types.ts` — `Item` est une _union discriminée_ : tester `item.type` suffit pour que TypeScript connaisse la forme de `item.content`.
- `lib/mind-map.ts` — fonctions sur l'arbre d'une carte mentale (racine, branches, sous-arbre, mise en page), sans React ni React Flow.

## Cartes mentales (phase 6)

On crée une carte mentale depuis le formulaire d'ajout (type « Carte mentale ») : seul le sujet central est demandé, puis l'éditeur s'ouvre.

| fichier                         | rôle                                                                        |
| ------------------------------- | --------------------------------------------------------------------------- |
| `mind-maps/[id]/page.tsx`       | Server Component : charge la carte, affiche l'éditeur                       |
| `mind-maps/[id]/actions.ts`     | Server Actions : enregistrer (tout l'arbre), supprimer                      |
| `mind-maps/mind-map-editor.tsx` | éditeur (client component), basé sur [@xyflow/react](https://reactflow.dev) |
| `mind-maps/mind-map-viewer.tsx` | la même carte en lecture seule, pour l'écran de révision                    |
| `mind-maps/topic-node.tsx`      | le composant d'un nœud (_custom node_ React Flow), partagé par les deux     |
| `mind-maps/flow.ts`             | conversions entre l'arbre stocké et les nœuds / arêtes de React Flow        |

**Édition.** Sélectionner une idée, puis : `Tab` ajoute un enfant, `Entrée` un voisin, `F2` ou un double-clic renomme, `Suppr` supprime l'idée et tout ce qui en part, `Ctrl+S` enregistre. On déplace une idée en la faisant glisser ; « Réorganiser » range tout l'arbre en colonnes. Les liens se créent uniquement par ces commandes, jamais en tirant un trait entre deux nœuds : c'est ce qui garantit que la carte reste un arbre.

**État local, puis enregistrement explicite.** L'éditeur travaille sur son propre état (`useNodesState`) et n'envoie l'arbre à l'API qu'au clic sur « Enregistrer ». Tant qu'il y a des modifications non enregistrées, c'est affiché, et quitter la page demande une confirmation.

**Le format stocké ne dépend pas de React Flow.** L'API garde `{ id, parentId, label, position }` ; React Flow ajoute ses propres champs (`selected`, `measured`, `type`…) qui n'ont rien à faire en base. `flow.ts` fait la conversion dans les deux sens, et les arêtes sont recalculées à partir de `parentId`.

**Révision.** Une carte de révision = une branche. `facesOf()` masque la branche demandée et toutes ses idées _côté serveur_ : leurs libellés ne sont pas dans le recto envoyé au navigateur. La forme de la branche (combien de sous-idées) reste visible, comme indice. Le verso montre la carte entière, avec la branche en surbrillance.

**Deux pièges rencontrés avec React Flow :**

- `colorMode="system"` est résolu dans le navigateur seulement : le HTML rendu côté serveur est en mode clair, le client passe en sombre, et React signale une erreur d'hydratation. Le mode sombre passe donc par les variables CSS de React Flow (`--xy-edge-stroke`…), dans `globals.css`, comme le reste de la page.
- React Flow cache un nœud (`visibility: hidden`) tant qu'il ne l'a pas mesuré, et un champ caché ne peut pas prendre le focus : sans précaution, la première lettre tapée dans une idée toute neuve était perdue. Un nouveau nœud reçoit donc une taille provisoire (`initialWidth` / `initialHeight`), ce qui le rend visible dès son premier rendu.

## Pourquoi le navigateur n'appelle plus l'API directement

En phase 2, le navigateur appelait l'API en `fetch`. Avec l'authentification, il faudrait lui confier le token, donc le stocker quelque part de lisible en JavaScript (localStorage), ce qui l'expose en cas de faille XSS.

À la place, Next.js joue le rôle d'intermédiaire (on parle de _Backend For Frontend_) :

1. Le formulaire de connexion appelle une **Server Action**, qui exécute `POST /auth/login` depuis le serveur Next.js.
2. Le JWT reçu est rangé dans un cookie **httpOnly** : le navigateur le renvoie automatiquement à Next.js, mais aucun script de la page ne peut le lire.
3. Pour afficher ou créer des quotes, Next.js lit le cookie et appelle l'API avec `Authorization: Bearer <token>`.

Conséquence : l'URL de l'API n'est plus exposée au navigateur, d'où `API_URL` au lieu de `NEXT_PUBLIC_API_URL`.

## Image Docker (phase 7)

`apps/web/Dockerfile` construit l'app avec `output: 'standalone'` (`next.config.ts`) : en plus du build habituel, `next build` produit `.next/standalone`, un `server.js` autonome accompagné des seuls fichiers de `node_modules` réellement utilisés (environ 40 Mo). L'image finale ne contient que ce dossier et les fichiers statiques (`.next/static`, que Next.js laisse de côté, car un CDN les servirait normalement).

- **`outputFileTracingRoot`** : dans un monorepo pnpm, les dépendances sont dans le `node_modules` de la racine. Next.js trace donc les fichiers depuis la racine du dépôt, et le serveur se retrouve dans `.next/standalone/apps/web/server.js`.
- **`API_URL` est lu à l'exécution, pas au build** : il n'est utilisé que côté serveur (pas de `NEXT_PUBLIC_`), et toutes les pages sont dynamiques. La même image fonctionne quelle que soit l'adresse de l'API ; `docker-compose.yml` la fixe à `http://api:3000`, le nom du service sur le réseau Docker.
- **`HOSTNAME=0.0.0.0`** : par défaut le serveur n'écoute que dans le conteneur ; il doit écouter sur toutes les interfaces pour que le port publié fonctionne.
- **Cookie de session en production** : l'image tourne avec `NODE_ENV=production`, donc le cookie est `Secure` (HTTPS seulement). Chrome, Edge et Firefox font une exception pour `http://localhost` (vérifié avec Chromium), ce qui suffit en local ; la phase 8 apportera HTTPS.

## Note sur les imports

Contrairement à `apps/api` (NodeNext + imports `.js` explicites), Next.js résout les modules TypeScript via `moduleResolution: "bundler"` : pas d'extension sur les imports relatifs (`from './lib/api'`, pas `'./lib/api.js'`). Chaque app garde la convention par défaut de son framework.
